## 一、启动与窗口

### Q1. 双击启动器「一闪而过」，什么都没发生

最常见的原因是**启动器不知道该启动什么**，或者**启动就崩了**。

排查顺序：

1. **先看有没有 `venv`**。启动器会检查 `venv\Scripts\python.exe`，不存在时弹「没有找到运行环境」（`launcher.py:88-90`）。没弹框说明程序根本没起来，或者弹框被关掉了。
2. **手工运行看报错**。命令行里执行：

   ```bat
   venv\Scripts\python.exe app.py
   ```

   窗口留住了就说明是启动器/窗口层的问题；直接报错就是环境问题，按报错修。
3. **用 `start.bat` 启动**（走浏览器而不是原生窗口）。如果 `start.bat` 能起、双击 exe 起不来，就是窗口层的问题 → 见 Q3。
4. **端口被占**。启动器会先探测端口；如果 7861 已被另一个 VocalSeparator 占用，它会直接开窗口而不是再起一个。但如果是别的程序占了 7861，`app.py` 会启动失败 → 见 Q24。

`launcher.py` 会等最多 **300 秒**等 HTTP 200。机器冷启动时首次 import torch 比较慢，属正常。

> 如果 `app.py` 闪退且来不及看报错，在 cmd 里运行它——窗口不会自动关闭。

---

### Q2. 浏览器打开了，但页面一直转圈 / 空白

1. 地址栏确认是 `http://127.0.0.1:7861`。
2. 若开成 `7860`：**这是过时文档的错误**。端口是 **7861**，只绑 127.0.0.1。
3. 等首次加载完成——首启动要 import torch + onnxruntime，**可能几十秒**。
4. 换一个浏览器试试。Gradio 6.x 对浏览器版本有要求，过旧的 IE 内核不行。

---

### Q3. 没有弹出原生窗口，只在浏览器里打开

正常的**降级路径**。启动器打开窗口的顺序是：

1. **pywebview + WebView2**（首选，原生窗口）
2. **Chrome / Edge 的 `--app=` 模式**（无地址栏的独立窗口）
3. **系统默认浏览器**（普通标签页）

落到第 2 或第 3 步，说明 WebView2 运行时缺失或加载失败。

想看是哪一个，看 `logs\` 里启动器输出的路径提示。

**影响**：只是外观。功能一样，但 WebView2 模式下下载文件走的是内置的 `JsApi.save_file`（保存到「下载」文件夹），而浏览器模式用浏览器自己的下载逻辑。

想装 WebView2：Windows 11 自带；Windows 10 可能需要装 [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。

---

### Q4. 关闭窗口后进程还在 / 任务还在跑

**这是有意设计**。分离任务跑在后台线程里（`app.py` 的任务线程模型），窗口只是「显示器」。

- 想**真的停下**：双击 `停止 VocalSeparator.bat`（按端口 7861 找进程并结束）；
- 想**暂停**：用页面上的暂停按钮（见[使用手册](使用手册.md)），比杀进程干净——杀进程会留下半个输出文件。

## 二、模型

### Q5. 提示「找不到模型」或「本地缺少模型文件」

程序是**完全离线**的：`HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1`，并且离线守卫把 `Separator.download_file_if_not_exists` 改成直接**抛异常**而不是去下载（`app.py:184-215`）。

所以看到「本地缺少模型文件 XXXXX，请放入 models\ 后重试」，含义是：**这个模型不在 `models\` 目录里，而且程序不会替你去下**。

处理：

1. 确认文件名完全一致（大小写、下划线、扩展名），放进 `models\`；
2. 跑 `python scripts\setup.py --check-models` 看缺哪些；
3. 内置的 8 个模型见[部署与打包](部署与打包.md#models--模型权重)。

> 为什么不做成自动下载：目标是**离线可用、可复现**。自动下载会让「装好就能跑」变成「装好还得看网」。

---

### Q6. 我想用的模型在模型库里，但选了报错

`catalog.json` 有 **169 个模型条目**、8 个分类桶、9 个社区预设，但**大部分权重不在本地**。

- 模型库里能选 ≠ 权重存在；
- 能直接跑的是 `BUILTIN_MODELS` 里那 8 个（`app.py:645-654`）；
- 社区预设（`vocal_full` / `instrumental_full` / `karaoke` 等）需要**非内置权重**，得自己下好放进 `models\`。

**关于 De-Reverb-Echo V2 与 Fused**：这两个确实**不在** `BUILTIN_MODELS`（`app.py:645-654`）里，而在 `DEREVERB_CHOICES`（`app.py:661-674`）里。**发布策略是：Release 提供的完整模型包覆盖 `BUILTIN_MODELS` + `DEREVERB_CHOICES` 用到的全部权重，因此包含 V2 与 Fused。**

所以：

- **用一键安装包安装的**：payload 里已经带了这些权重，选这两项能直接跑；
- **从源码搭建的**：`python scripts\fetch_assets.py models` 只能取到有公开直链的那几个，**其余（含 V2 / Fused）随 Release 模型包获取**，放进 `models\`。

选这两项报「缺少模型文件」，就是 `models\` 里少了对应对应 `.ckpt`——按[部署与打包](部署与打包.md#可选去回声模型)补齐即可。

---

### Q7. 官方模型包能自动下载吗？

`scripts/fetch_assets.py models` 只能自动下**有公开直链**的少数几个，其余会打印查找提示让人工获取。原因见[部署与打包](部署与打包.md#models--模型权重)。

## 三、分离效果

### Q8. 去回声之后，人声整体变小了

**已知特性，已做补偿，但仍可能残留。**

去混响模型会整体衰减输出（有些曲目衰减超过 10 dB），所以后处理里有一步 **RMS 响度匹配**，增益被钳在 `[0.2, 12.0]`，也就是最多补 **+21.6 dB**（`app.py:1120-1150`）。已经补过了还不满意，说明该曲目的衰减超出了钳制范围，或者匹配是基于整段的、局部段落仍有起伏。

想手动处理：在 DAW / 音频编辑器里对该轨做一次响度归一化。

> 为什么要有上限：不设上限时，遇到衰减极大的曲目会把底噪和残留回声一起抬起来。

---

### Q9. 去回声之后声音「变闷」/ 高频没了

先确认 **`restore_air` 是不是开着的**。

`restore_air`（8 kHz 以上高频补偿）对**新的 De-Reverb-Echo 系列默认关闭**——因为这类模型本身不掉高频，硬补高频会把回声能量一起提回来（`app.py:1160-1200`）。

如果用了旧的 anvuew 系列觉得闷，可以手动打开 `restore_air`。

后处理里还有一步 **1/3 倍频程宽带频谱倾斜匹配**（`_spectral_tilt_match`，`app.py:1091-1119`）：把输出人声的宽带频谱倾向往输入人声拉近，钳制 **±6 dB**（`max_db=6.0`），作用范围 180 Hz ~ 16 kHz。

**它故意不做窄带 / 共振峰增强**——窄带提升会把被压下去的回声能量重新抬回来。所以「听起来不如暴力 EQ 亮」是设计取舍，不是 bug。

---

### Q10. 去回声模型（anvuew）效果很差，几乎没用

**选错模型了。** anvuew 系列是**去混响（dereverb）**模型，对**离散回声**几乎无效。

离散回声要用 **Sucial De-Reverb-Echo 系列**：

| 选项 | 定位 |
| --- | --- |
| **De-Reverb-Echo V2** | **推荐**，处理回声 |
| Fused | 融合版 |
| 标准 anvuew (SDR 19.17) | 去混响 |
| 轻柔 anvuew (SDR 18.81) | 去混响，更保守 |
| 双模型串联 V2→Fused | 两次串行，最慢 |

---

### Q11. 去回声跑两遍会不会更好？

**几乎不会，而且要花两倍时间。**建议只跑 **1 遍**。

原因：第二遍的输入已经是「回声被压掉一大半」的信号，模型没有足够多的回声能量可供识别，收益递减；而推理时间随遍数线性增长。

---

### Q12. 人声和伴奏分离得不干净 / 有串音

按这个顺序调：

1. **换成集成组合**。「内置集成组合」用 2~3 个模型加权平均，通常比单模型干净（见[使用手册](使用手册.md)的档位选择）。
2. **减小 overlap**。overlap 越大越慢，但边界拼接更平滑——注意实测显示 overlap 对**速度**影响巨大（8→32 约 4 倍慢）、对**质量**的提升不如换模型明显（官方默认 4，8 是更保守的可选值，见[原理与架构](原理与架构.md)）。
3. **加大 demucs shifts**（仅多轨 Demucs 有意义），代价是时间线性增长。
4. 确认选的是对的**主轨**——`DEREVERB_PRIMARY_STEM` 决定后处理作用在人声还是伴奏上。

## 四、性能与显存

### Q13. `CUDA 可用：False`，跑得极慢

说明 torch 装成了 CPU 版。

```bat
venv\Scripts\python.exe -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

版本号里**没有 `+cu128`** 就是 CPU 版。重装：

```bat
venv\Scripts\python.exe -m pip install torch torchaudio torchvision ^
    --index-url https://download.pytorch.org/whl/cu128
```

还要确认：NVIDIA 驱动较新（CUDA 12.8 时代）、`nvidia-smi` 能正常输出。

---

### Q14. 显存不足 OOM（`CUDA out of memory`）

按代价从低到高：

1. **降低 `batch_size`**（默认 8，可降到 4 甚至 1）；
2. **换更小的模型**——Mel-Band gabox 比 Revive V3e **快约 2.5 倍**，显存占用也更友好；
3. **不要同时开集成 + 大 batch**——集成要逐个模型推理，但峰值显存仍受单模型 batch 影响；
4. **关掉其它占显存的程序**（游戏、另一个推理任务、浏览器硬件加速）；
5. **别同时提交多个任务**。全局串行锁 `RUN_LOCK` 保证同一时刻只有一个任务在推理，所以多任务是排队、不会叠加显存——但如果你开了别的 GPU 程序，就会叠加。

> 显存不足的完整报错会写进 `logs\`，可用来确认到底是哪一步炸的。

---

### Q15. 分离很慢，但显卡占用很低

先看 GPU 占用是「低」还是「波动」——波动是正常的（chunk 之间有 CPU 侧开销）。持续很低的话按顺序查：

1. **确认在跑 GPU**。`CUDA 可用：False` 的时候 torch 会在 CPU 上跑，此时显卡占用就是 0。见 Q13。
2. **`overlap` 是不是调大了**。这是**最大的性能变量**：实测 overlap 从 8 调到 32 大约慢 **4 倍**（`overlap` 决定相邻 chunk 的重叠比例，重叠越多推理次数越多）。**官方默认值是 4**（见[原理与架构](原理与架构.md)的说明，`OVERLAP_LABEL`，`app.py:4822`），**8 是更保守的可选值**——别随手往大调。
3. **看「环境」页的实测对比**。页面上有个「实测对比」按钮，会在 60 秒片段上跑 6 种配置，直接给你本机数字。

**已经实测过的结论（环境页同一入口可得）**：`CPU 线程数` / `cudnn.benchmark` / `batch_size` 三个参数的差异 **< 15%**——因为瓶颈在 GPU 推理。**不要在这三个参数上折腾**，收益很小。

4. 长音频本身就要时间：推理量大致随**时长**线性增长。

---

### Q16. 多任务提交后显示「排队」，是不卡了吗

**不是卡住，是设计。**全局信号量 `RUN_LOCK` 保证**同一时刻只有一个任务在做推理**。后来提交的任务状态是 `排队`，阶段文案「排队中 · 前一个任务完成后自动开始」。

这样做的原因：并发的多次 GPU 推理会互相抢显存，反而都变慢甚至 OOM；串行虽然晚开始，但总吞吐更高、不会爆。

界面上的轮询不会因此卡住——`demo.queue(default_concurrency_limit=4)` 留了并发额度给轮询请求（`app.py` 的 `demo.queue` 配置）。

---

### Q17. 关了页面 / 刷新浏览器，任务会丢吗

**不会。** 任务跑在**后台线程**里，状态写在 JSON 台账 `tasks.json`（`TaskLedger`，`app.py:320`）。刷新、切标签、关页面都不影响。

页面靠**单个 `gr.Timer`** 驱动三个列表的刷新，所以刷新页面能重新渲染出当前全部任务。

> 顺带一提，轮询做过一次重写：早期实现每次轮询都会重建组件，导致刷新页面时进度跳变、组件重建、界面闪烁。现在每个浏览器会话有独立去重缓存（`_sess` / `_new_sid` / `_cached_upd` / `_cached_choices`），只有真正变化时才推组件更新。

---

### Q18. 暂停了但进度条还在动

**是正常运行状态，不是 bug。**进度采用**单调不减**策略：暂停后进度条停在当前值，但已进入的推理 chunk 必须跑完才能安全停下（中途强停会留下不完整的输出）。

恢复用「继续」，不会从头开始。

## 五、文件与清理

### Q19. 输出文件在哪？

| 位置 | 内容 |
| --- | --- |
| `<安装目录>\output\` | 所有分离结果 |
| `<安装目录>\output\_export\` | 「导出任务详情」产生的 md / zip |
| `<安装目录>\logs\` | 运行日志，排查问题时先看这里 |

页面上「全部输出文件（可下载/试听）」那一栏能直接下载。

**原生窗口模式（pywebview）下**，点下载会把文件**复制一份到你的「下载」文件夹**——因为 WebView2 不原生处理下载，启动器的 `JsApi.save_file` 做了这件事。

---

### Q20. 「下载后自动清理本机副本」是什么意思？会真的删掉吗？

**会从输出目录移走，但进的是回收站，不是永久删除。**

流程：

1. 你在浏览器里点了下载；
2. 前端下载完成后 `POST /vs_del` → 调用 `vs_mark_downloaded`（`app.py` 的 `_vs_del` 路由）；
3. 后台把该文件送进**回收站**（`_to_recycle_bin`，`app.py:1872+`）。

实现用的是 Windows 原生 Shell API（`ctypes` 调 `SHFileOperationW`），flags 含 `FOF_ALLOWUNDO`，所以**在回收站里能找回**。

已经下到「下载」文件夹的那份不受影响。

> 为什么要清理：分离输出动辄几百 MB，批量跑完很容易把盘塞满。

---

### Q21. 怎么把所有任务的记录导出成一份文档？

页面上有两个导出：

- **导出任务详情**：单个任务的 Markdown（`_task_detail_md`，标题为 `# 任务详情 · {id}`）；
- **导出全部任务**：返回消息里同时给出 md 与 zip 的路径。

导出产物在 `output\_export\`。

## 六、格式与兼容

### Q22. 支持哪些音频格式？

输入白名单（`app.py` 里的 `AUDIO_EXTS`）：

```
.wav .mp3 .flac .m4a .aac .ogg .wma
```

上传组件支持目录（会自动 `rglob` 递归收集音频文件）。

**建议输入 wav**：解码无损，省一次有损解码的损失。mp3 / m4a 也能用，但本身已经是有损格式，模型能得到的信息就少一些。

输出格式在「输出与参数」里选。

---

### Q23. 长音频 / 批量要注意什么？

- **时间随总时长线性增长**。批量就是把单曲的耗时累加，没有魔法加速。
- **先拿一首 60 秒片段试**，确认模型 / 参数组合满意再全量跑。环境页的「实测对比」就是干这个的。
- **磁盘**：一条 3 分钟的立体声 wav 约 30 MB，两条轨就 60 MB。批量几十首很容易上 GB。建议打开「下载后自动清理」。
- **排队**：批量任务之间也是串行（`RUN_LOCK`），别以为提交完就并行跑了。
- **overlap 保持官方默认值 4**（`OVERLAP_LABEL`，`app.py:4822`；8 是更保守的可选值），全量跑之前不要为了「质量更好」把 overlap 拉大。

---

### Q24. 端口 7861 被占用，起不来

```bat
netstat -ano | findstr :7861
tasklist | findstr <上一步的PID>
```

- 如果占用者是**上一个 VocalSeparator**：双击 `停止 VocalSeparator.bat`，或 `taskkill /PID <PID> /F`，再启动。
- 如果是**别的程序**：先把它关掉。程序固定用 7861，且只绑 127.0.0.1（外部机器访问不到）。

> 注意端口是 **7861**，不是 7860。旧版部署说明里的 7860 是错的。

---

### Q25. 能不能不用 NVIDIA 显卡？

**能跑，但很慢。**装 CPU 版 torch 即可：

```bat
venv\Scripts\python.exe -m pip install torch torchaudio torchvision
```

（不带 `--index-url`。）

- 功能完整，模型、集成、去回声都能用；
- 速度大约是 GPU 的**十分之一或更慢**（取决于 CPU 和模型）；
- 在「环境」页把 **CPU 线程数**调到物理核心数，并打开 **cudnn.benchmark**……注意实测结论是这两个参数差异 **< 15%**，所以**不要指望靠调参救回 CPU 的速度**。

> AMD / Intel 显卡：本项目的 `onnxruntime-gpu` 与 torch CUDA 构建都不支持，只能用 CPU。

---

### Q26. 怎么换模型 / 加自己的模型？

**换内置模型**：单模型模式的下拉里选——标签已经标注了「推荐 / 速度 / 擅长轨」。

**加新模型**：

1. 把 `.ckpt`（配套的 `.yaml` 若有）放进 `models\`；
2. 想在下拉里出现，需要加进 `BUILTIN_MODELS`；
3. 想进「模型库」页，加进 `catalog.json`。

具体步骤见 [CONTRIBUTING.md](../CONTRIBUTING.md)。

**多轨 Demucs**：需要 `htdemucs_ft.yaml` + `htdemucs_ft.th`（4 轨）或 `htdemucs_6s.yaml` + `htdemucs_6s.th`（6 轨），两个文件**必须成对**且同名，放进 `models\`。

## 七、卸载与杀软

### Q27. 杀毒软件报毒 / 拦截启动器

**误报，很常见。**触发点通常是：

- `VocalSeparator.exe` 是 PyInstaller 打包的启动器——PyInstaller 产物是杀软启发式扫描的重灾区；
- 安装程序会**解压 + 写注册表 + 建快捷方式**，行为特征像安装器；
- `停止 VocalSeparator.bat` 用 `taskkill` 结束进程。

这些都是本地、可见、无网络行为的操作。

处理：

1. 把安装目录加进杀软**白名单 / 排除目录**；
2. 从**官方 Release 页面**下载，并核对 `RELEASE_SHA256SUMS.txt` 里的哈希（用 `scripts/pack_release.py manifest` 同一套算法生成）；
3. 还报就把具体报毒名和被杀的文件贴到 Issues。

> 程序运行期**不联网**（`HF_HUB_OFFLINE=1` / `TRANSFORMERS_OFFLINE=1` / 离线守卫），也不监听除了 `127.0.0.1:7861` 之外的任何地址。如果杀软说它「外联」，那更可能是误报。

### Q28. 卸载不干净，目录 / 快捷方式 / 注册表项还在

按顺序清理：

1. **卸载程序本身失败**（比如 `rmdir` 被占用挡住）：手工删 `%LOCALAPPDATA%\VocalSeparator`。删之前先确保没有进程占用（`停止 VocalSeparator.bat`）。
2. **快捷方式残留**：
   - `桌面\VocalSeparator.lnk`
   - `%APPDATA%\Microsoft\Windows\Start Menu\Programs\VocalSeparator.lnk`
   - 同目录的 `卸载 VocalSeparator.lnk`
3. **注册表残留**（都在 HKCU，`regedit` 里直接删）：

   ```
   HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\VocalSeparator
   HKCU\Software\Microsoft\Windows\CurrentVersion\App Paths\VocalSeparator.exe
   HKCU\Software\VocalSeparator
   ```

   `uninstall.py:10-14` 定义了这三个键。

4. **「已安装的应用」里还留着一行**：把它清掉就是删上面第一个键，或重新运行一次 `卸载 VocalSeparator`。

**不放心的话**：先在「设置 → 应用」里走官方卸载，再手工核对上面三处。全程不需要管理员权限。

### Q29. 安装包 12.56 GB 下载太慢 / 老是断

Release 托管在境外，国内直连确实可能很慢。两个办法：

**办法一（推荐）：走 123 云盘镜像**

> 链接：**https://1843626542.share.123pan.cn/123pan/VX07Td-o8MmA?pwd=yx7y**\
> 提取码：**`yx7y`**

云盘里是**同一份内容**，且已打包成单个文件，不需要凑齐 7 个分卷。缺点：第三方网盘可能限速、要登录、也可能随时间失效。

**办法二：只下源码 + 按需拉模型**

源码只有 **2.32 MB**，`git clone` 后按 [方式 B](部署与打包.md#方式三从源码部署开发者) 装依赖，
模型用 `python scripts\fetch_assets.py models` 或直接从 Release 的模型包取需要的几个
（8 个内置模型里，单曲分离通常只需要 `bs_roformer_vocals_revive_v3e_unwa.ckpt` 一个）。

> ⚠️ **GitHub Release 是长期唯一官方来源**。网盘链接失效、或内容与 Release 对不上时，一律以 Release 为准并核对 `RELEASE_SHA256SUMS.txt`。
