## 先搞清楚一件事：仓库里没有大文件

GitHub 单文件上限 100 MB，而模型权重单个就有几百 MB 到 1 GB+。因此**仓库里只放代码与文档（< 5 MB）**，以下内容**不进 Git**（见 `.gitignore`）：

| 目录 | 内容 | 体积 | 怎么拿 |
| --- | --- | --- | --- |
| `models/` | AI 模型权重 | 数 GB | Release 附件 / `scripts/fetch_assets.py` |
| `bin/` | FFmpeg | ~200 MB | Release 附件 / `scripts/fetch_assets.py` |
| `runtime/` | 自带 Python 运行时 | ~90 MB | Release 附件 |
| `venv/` | 虚拟环境 | 5~7 GB | 本地安装生成 |
| `dist_send/` | 打包产物（安装包 + payload） | ~17 GB | 本地构建生成 |

`scripts/pack_release.py:3-7` 的说明：

> 仓库本身只存代码与文档（<5 MB）。模型（约 7 GB）、FFmpeg（约 200 MB）、自带 Python 运行时（约 90 MB）都走 GitHub Release 或用户自行下载 —— GitHub 单文件上限 100 MB，直接提交必然失败。

**所以：clone 完仓库是不能直接跑起来的**，必须补齐 `models\` 和 `bin\`。

## 方式一：下载 Release 安装包（推荐给普通用户）

1. 到 Releases 页面下载**安装程序**（`VocalSeparator-Setup.exe` 和同名 `payload*.7z`，放**同一个文件夹**）。
2. 双击 `VocalSeparator-Setup.exe`。
3. 安装程序是一个图形界面（WebView2），会自动解压并部署。
4. 装完后桌面和开始菜单出现 `VocalSeparator` 快捷方式，双击即可用。

**不需要管理员权限**，所有文件都装进 `%LOCALAPPDATA%\VocalSeparator`。

耗时参考：作者机器上实测约 **150~160 秒**（大头是把约 8.2 GB 的 payload 解压到本地磁盘）。

---

## 方式二：绿色包 + 一键安装（推荐给想自己放模型的人）

绿色包 = 仓库代码 + `models\` + `bin\` + `runtime\`，拷到哪台机器都能用。

1. 拿到绿色包目录，拷到目标机器任意位置，例如 `D:\VocalSeparator`。
   - **路径不要含中文和空格**（个别依赖有编码问题）；
   - `models\`（模型）和 `bin\`（FFmpeg）**缺一不可**，别只拷单个文件。
2. 双击 **`一键安装.bat`**。
3. 脚本按 5 步自动完成（见 `一键安装.bat`）：
   - `[1/5]` 查找本机 Python（优先 3.12 → 3.11 → 3.10）；
   - `[2/5]` 在包内创建 `venv` 虚拟环境（不污染系统 Python）；
   - `[3/5]` 从 PyTorch 官方源装 `torch / torchaudio / torchvision`（CUDA 12.8），失败自动回退 CPU 版；
   - `[4/5]` 从清华镜像装 `requirements.txt`，失败换阿里镜像；
   - `[5/5]` 环境自检（import torch / gradio、CUDA 可用性）。
4. 看到 `安装完成 ✓` 后关闭窗口。
5. 双击 `start.bat` 启动，或 `python launcher.py` 用原生窗口启动。

耗时参考：网速正常时 **10~25 分钟**（大头是 torch 下载安装）。

> 脚本还会检查 `bin\ffmpeg.exe` 和 `models\*.ckpt` 是否存在，缺失时提示去本文档找下载方式。

## 方式三：从源码部署（开发者）

```bash
git clone <repo-url>
cd VocalSeparator
```

### 1. 建虚拟环境

要求 Python **3.10 ~ 3.12**（推荐 3.12）：

```bash
python -m venv venv
```

### 2. 先装 CUDA 版 PyTorch

**这一步必须单独做，且必须在装 `requirements.txt` 之前**——因为 `torch` 的 `+cu128` 本地版本标记在 PyPI 上不存在（`requirements.txt:4-10` 的注释已说明，torch 系列在该文件里只是注释）。

```bash
venv\Scripts\python.exe -m pip install --upgrade pip setuptools wheel

venv\Scripts\python.exe -m pip install torch torchaudio torchvision ^
    --index-url https://download.pytorch.org/whl/cu128
```

> 没有 NVIDIA 显卡就把 `--index-url` 那行去掉，装 CPU 版（能用但慢很多）。

### 3. 再装其余依赖

```bash
venv\Scripts\python.exe -m pip install -r requirements.txt ^
    -i https://pypi.tuna.tsinghua.edu.cn/simple
```

`requirements.txt` 是**纯 ASCII** 的——故意如此，因为 pip 会用系统区域设置解码它（`requirements.txt:11`）。

### 4. 准备本地资源

- 把 FFmpeg 的 `ffmpeg.exe` / `ffprobe.exe` 放进 `bin\`；
- 把模型权重放进 `models\`；
- 或者用脚本自动拉：

```bash
venv\Scripts\python.exe scripts\fetch_assets.py list    # 先看要下什么、多大
venv\Scripts\python.exe scripts\fetch_assets.py ffmpeg  # 下 FFmpeg
venv\Scripts\python.exe scripts\fetch_assets.py models  # 下能自动下的模型
```

### 5. 自检 + 启动

```bash
venv\Scripts\python.exe scripts\setup.py          # 环境自检
venv\Scripts\python.exe scripts\setup.py --check-models   # 只查模型
venv\Scripts\python.exe app.py                    # 启动
```

也可以直接双击 `start.bat`。

### 一键脚本

`scripts/setup.py --install` 等价于上面第 1~3 步，适合 CI 与自动化部署（`scripts/setup.py:3-12`）：

```bash
python scripts/setup.py --install
```

## 模型与 FFmpeg 从哪来

**这两样都不在仓库里**，必须补齐，否则装好了也跑不了。

### `bin\` —— FFmpeg

必须有两个文件：

```
bin\
├─ ffmpeg.exe
└─ ffprobe.exe
```

- `ffmpeg.exe` 负责音频解码/编码；
- `ffprobe.exe` 负责读时长（`app.py:242` 的 `probe_duration()` 用它算 ETA）。

来源：

```bash
python scripts/fetch_assets.py ffmpeg
```

脚本从 gyan.dev 拉 `ffmpeg-release-essentials.zip`，只提取这两个 exe（`scripts/fetch_assets.py:32`）。

也可以自己下载任意 Windows 构建，手工放进 `bin\`。

### `models\` —— 模型权重

程序需要 **8 个内置模型**（`app.py:645-654` 的 `BUILTIN_MODELS`）：

| 文件名 | 用途 |
| --- | --- |
| `model_bs_roformer_ep_317_sdr_12.9755.ckpt` | BS-Roformer 1297（人声/伴奏均衡） |
| `model_bs_roformer_ep_368_sdr_12.9628.ckpt` | BS-Roformer 1296 |
| `bs_roformer_vocals_revive_v3e_unwa.ckpt` | Revive V3e（**默认单模型**，人声最干净） |
| `melband_roformer_instvox_duality_v2.ckpt` | InstVoc Duality V2 |
| `mel_band_roformer_instrumental_fv7z_gabox.ckpt` | 伴奏专用，快 2.5 倍 |
| `mel_band_roformer_karaoke_aufr33_viperx_sdr_10.1956.ckpt` | 卡拉 OK |
| `dereverb_mel_band_roformer_anvuew_sdr_19.1729.ckpt` | 去混响 标准 |
| `dereverb_mel_band_roformer_less_aggressive_anvuew_sdr_18.8050.ckpt` | 去混响 轻柔 |

`scripts/fetch_assets.py models` 只能自动下前两个（有公开直链），其余会打印**查找提示**让你手动获取（`scripts/fetch_assets.py:46-55`）：

```
以下 N 个模型没有公开直链，需要手动获取后放进 models\：
  - bs_roformer_vocals_revive_v3e_unwa.ckpt
      unwa 的 vocals revive 系列，见 HuggingFace unwa/ 仓库
```

**完整内置模型集合随 Release 的「模型包」提供。**

### 可选：去回声模型

`DEREVERB_CHOICES`（`app.py:661-674`）里的 **De-Reverb-Echo V2** 和 **Fused** 是推荐的去回声模型，但**不在 `BUILTIN_MODELS` 列表里**——想让这个选项可用，需要额外放入：

| 文件名 | 说明 |
| --- | --- |
| `dereverb-echo_mel_band_roformer_sdr_13.4843_v2.ckpt` | De-Reverb-Echo V2（**推荐**） |
| `dereverb_echo_mbr_fused.ckpt` | Fused |

不放入时，去回声下拉里选中这两项会因离线守卫直接报「本地缺少模型文件」。

### 可选：多轨 Demucs

想要鼓 / 贝斯 / 吉他 / 钢琴分轨，需要 Demucs v4 权重（`.yaml` + 同名 `.th` 成对）：

| 文件 | 轨数 |

放在 `models\` 里即可（`README.md:45`）。

python scripts/setup.py --check-models

它会比对 `models\` 目录、`catalog.json` 与 `app.py` 里的 `BUILTIN_MODELS`（`scripts/setup.py:108-132`），缺哪个直接列出来。

## 发布安装包怎么打

用 `scripts/pack_release.py`，共三个子命令 + 一个全做：

### 1. `manifest` —— 生成校验清单

```bash
python scripts/pack_release.py manifest
```

扫描 `models/`、`bin/`、`runtime/`（`scripts/pack_release.py:47`），逐个算 SHA256，产出：

- `release_manifest.json` — 机器可读（文件名 / 字节数 / sha256）；
- `RELEASE_SHA256SUMS.txt` — 人可读，附在 Release 说明里供用户校验。

### 2. `assemble` —— 组装绿色包

```bash
python scripts/pack_release.py assemble --out D:\VocalSeparator-green
```

把**仓库代码**（`CODE_ITEMS`，`scripts/pack_release.py:38-44`）和**本机大文件**（`HEAVY_DIRS = ["models", "bin", "runtime"]`）合到一起，并在根目录写一份 `【这是什么】.txt`（`scripts/pack_release.py:155-170`）。

加 `--force` 覆盖已存在的目标目录。

### 3. `payload` —— 打成安装程序要的 7z

```bash
python scripts/pack_release.py payload --src D:\VocalSeparator-green
```

用 7-Zip 压缩（`scripts/pack_release.py:209`）：

```
7z a -t7z payload.7z .\* -mx=1 -mmt=on
```

- `-mx=1` 快速模式：模型本身已是压缩格式，低压缩档能省大量时间；
- 需要分卷（例如传到体积受限的网盘）时加 `--volume 1900m`；
- 7z 可执行文件的查找顺序：`bin\7z.exe` → 仓库根 `7z.exe` → `C:\Program Files\7-Zip\7z.exe` → PATH 里的 `7z` / `7za`（`scripts/pack_release.py:181-186`）。

**产物必须和 `VocalSeparator-Setup.exe` 放在同一文件夹**才能分发。

### 4. 一次全做

```bash
python scripts/pack_release.py all --out D:\VocalSeparator-green
```

等价于 `manifest` + `assemble` + `payload`。

### payload 里装了什么

安装程序期望的顶层结构（`PAYLOAD_ITEMS`，`scripts/pack_release.py:50-53`）：

```
app.py, launcher.py, installer_web.py, uninstall.py,
catalog.json, requirements.txt,
start.bat, 停止 VocalSeparator.bat, 一键安装.bat,
README.md, LICENSE,
assets, ui, show, docs, scripts,
venv, models, bin, runtime,
VocalSeparator.exe
```

注意 payload 里**包含已经建好的 `venv`**——这是安装包体积大的主要原因。安装程序会把 `venv\pyvenv.cfg` 里的 `home` / `executable` 改写成随包分发的 `runtime\python311`。

## 安装程序做了什么

`installer_web.py` 是一个 **pywebview / WebView2** 图形安装程序（界面定义在 `ui/installer.html`）。

> 为什么不用 Tkinter：透明分层窗口导致鼠标命中异常（关闭按钮点不动）、每帧 CPU 合成大图堵死主循环、高 DPI 下字糊。

流程：

1. 定位 `payload.7z`（约 8.2 GB），用 7z 解压到 `%LOCALAPPDATA%\VocalSeparator`；
2. 改写 `venv\pyvenv.cfg` 的 `home` / `executable`，指向打包自带的 `runtime\python311`——这样目标机**不需要装 Python**；
3. 自检：尝试 `import torch` / `import gradio`，确认环境可用；
4. 创建**桌面**和**开始菜单**快捷方式；
5. 写注册表卸载项（**全部在 HKCU 下，不需要管理员权限**）。

### 写入了哪些注册表项

`uninstall.py:10-14` 定义了完整的键列表（也就是安装时写入的）：

```
HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\VocalSeparator
HKCU\Software\Microsoft\Windows\CurrentVersion\App Paths\VocalSeparator.exe
HKCU\Software\VocalSeparator
```

### 快捷方式位置

- 桌面：`VocalSeparator.lnk`
- 开始菜单：`%APPDATA%\Microsoft\Windows\Start Menu\Programs\VocalSeparator.lnk`
- 开始菜单（卸载）：同目录下的 `卸载 VocalSeparator.lnk`

### 预计耗时

作者机器实测约 **150~160 秒**。机械硬盘或杀软实时扫描会明显更慢。

安装日志：`installer_web.log`（在安装程序所在目录）。

## 卸载

三种方式：

1. **设置 → 应用 → 已安装的应用 → VocalSeparator → 卸载**（走注册表里的卸载项）；
2. 开始菜单的 **卸载 VocalSeparator** 快捷方式；
3. 直接运行安装目录下的 `python uninstall.py`。

`uninstall.py` 会：

1. 用 PowerShell 删除桌面与开始菜单的三个快捷方式（`uninstall.py:20-27`）；
2. 删除上面三个 HKCU 注册表项（`uninstall.py:31-38`）；
3. 起一个延迟 2 秒的 `rmdir /s /q` 删掉安装目录本身（`uninstall.py:41`）——延迟是为了让当前进程先退出。

卸载不干净怎么办见 [常见问题](常见问题.md#卸载不干净)。

## 离线安装（目标机没网）

### 方式 A：wheels 目录

在打包机导出 wheels：

```bash
python scripts/pack_release.py manifest   # 顺带确认体积
# 需要自行用 pip download 导出到 wheels\
```

把带 `wheels\` 的包拷到目标机后，安装脚本会**优先使用本地包离线安装**。

### 方式 B：整包分发（更省事）

直接分发**绿色包 + 已建好的 `venv`**（也就是 Release 安装包的 payload 方式）。安装程序只解压、改配置、自检，**不联网**。

这是最稳的离线路线：目标机不需要装 Python，也不需要 pip。

### 方式 C：手工拷 venv

把整个 `venv\` 拷过去。体积大，且要求目标机路径与原机差异不大（`venv\pyvenv.cfg` 记的是绝对路径）。**非官方推荐**，遇到问题优先用方式 A / B。

## 常见构建问题

### Q：`pack_release.py payload` 提示找不到 7z

```
找不到 7z.exe / 7za —— 请先安装 7-Zip 或把 7z.exe 放进 bin/
```

装 [7-Zip](https://www.7-zip.org/)，或把 `7z.exe` 放进 `bin\`。

### Q：`assemble` 说「目标已存在」

加 `--force`。

### Q：payload 体积和预期不符

`-mx=1` 是快速模式，压缩率低是**正常的**——模型权重本身已是压缩格式，再压收益很小。体积主要来自 `models\` 和 `venv\`。

### Q：`manifest` 跳过某个目录

说明本机没有该目录（`scripts/pack_release.py:85-87` 会打印「跳过（不存在）」）。补齐 `models\` / `bin\` / `runtime\` 后重跑。

### Q：打包后安装成功但启动报「没有找到运行环境」

`launcher.py:88-90` 会在 `venv\Scripts\python.exe` 不存在时弹这个框。检查：

- payload 里的 `venv\` 是否完整；
- 安装程序是否成功改写了 `venv\pyvenv.cfg` 的 `home` 指向 `runtime\python311`。

或者点 `一键安装.bat` 重建 venv。

### Q：`pip install -r requirements.txt` 报 torch 找不到

`torch==2.11.0+cu128` **不在 PyPI 上**。必须先单独从 PyTorch 索引装（见[方式三](#方式三从源码部署开发者)第 2 步）。

### Q：安装后 `CUDA 可用：False`

多半是装了 CPU 版 torch。重装 CUDA 版：

```bash
venv\Scripts\python.exe -m pip install torch torchaudio torchvision ^
    --index-url https://download.pytorch.org/whl/cu128
```
